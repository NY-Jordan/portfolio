Multi-tenant SaaS sounds like a data-modeling problem first. In practice, the harder problem shows up in onboarding and pricing before it shows up in your schema.

## Data isolation is the easy part

Row-level tenant scoping, or separate collections per tenant, is a solved problem — pick one, document it, enforce it everywhere with a single access layer so nobody can bypass it by accident.

## Onboarding is the hard part

Zyraa's biggest churn risk wasn't a missing feature — it was showing every salon owner the full admin dashboard on day one. Progressive onboarding, where features unlock as a salon actually needs them, did more for retention than any single feature ship.

## Feature gating needs a single source of truth

Once you have paid tiers, "can this tenant see X" gets asked from the frontend, the backend, and background jobs. Centralize that check once — a `can(tenant, feature)` function — instead of re-implementing the plan logic everywhere it's needed.

## The pattern in one line

Isolate data by default, reveal features gradually, and gate everything through one function you trust.
